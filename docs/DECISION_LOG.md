# PracticeSignal — Decision Log

> **Document type:** Architectural decision & rationale record.
> **Version:** 1.1 — 4 November 2026 (Phase 0.5 reconciliation).
> **Inputs:** Phase 0 architecture review findings (R1–R12, recommendations A1–A9) and the client's Phase 0.5 reconciliation instructions (§1–§9).
> **Change control:** any later deviation introduces a new dated decision entry; silent drift is prohibited.

| # | Decision | Status |
|---|---|---|
| **D1** | Rename the product **PracticeSignal** (working name CareScout is retired). The name is provisional: no trademark, domain or collision search has been performed, and no availability claim is made. A collision search is tracked as an open item (IMPLEMENTATION_PLAN §9). | Accepted (client §1) |
| **D2** | All model-licensing statements corrected. Default model: **`llama3.2:3b`**, already installed on the host (verified: Ollama 0.40.14), served via a local-only Ollama HTTP adapter. Its **Llama 3.2 Community License** is documented accurately in this log and ARCHITECTURE §7. **We do not redistribute model weights** — the operator pulls the model from the official Ollama registry under the licence's own terms. Reference documents do not embed or ship model binaries. | Accepted (client §2; resolves R1) |
| **D3** | **No additional model downloads without a measured reason.** A benchmark record (tokens/s, latency p50/p95, JSON-validity rate at total-token budget) is the only acceptable evidence for changing the model. Apache-2.0 alternatives (Qwen family) remain documented fallbacks only. The previously considered Qwen2.5-3B is retired from recommendation: the 3B variant carries a restricted (non-Apache) licence, contradicting the zero-cost, freely-redistributable-tooling posture. | Accepted (client §2; extends A1) |
| **D4** | **One structured extraction call per unchanged-page rule**: a single structured-JSON call per *changed* snapshot (page classification + org facts + service/hours + vacancy candidates in one prompt); snapshots whose content hash is unchanged skip AI inference and reuse existing candidate facts. This supersedes the original six-stage sequential prompt flow, which was rejected after host verification confirmed **CPU-only inference** (no GPU) — multi-stage calls risked multi-minute per-page latency and a degraded demo. | Accepted (client §2; implements R2/A2) |
| **D5** | **Benchmark before creative freedom.** `scripts/benchmark_ai.py` measures CPU latency (p50/p95), tokens/sec, and JSON-validity rate against the selected prompt set. Prompt changes are accepted only against measured deltas, never intuition or verbosity preference. The benchmark is excluded from the default pytest run (skipped, not failed, when Ollama is not running) so environments without the model can still run the functional suite. | Accepted (client §2) |
| **D6** | **Field allowlist per source is the primary data-minimisation control.** Each registered source declares `intended_fields`; extraction candidates outside that allowlist are rejected deterministically before persistence — the model is never trusted as the privacy control. | Accepted (client §4) |
| **D7** | **Normalization failures preserve data.** If a value (e.g., opening hours) cannot be normalized deterministically, the raw value is stored unchanged with `needs_review`; normalization never invents a substitute, and there is no model fallback for normalization. | Accepted (client §2) |
| **D8** | **Deletion is review-act gated.** Removing a source cascades to its snapshots, facts, candidates, evidence and ingestion runs; the cascade is logged as a review action. No other destructive DB paths exist in application code. | Accepted (client §4; retention footprint minimised) |
| **D9** | **Incremental database.** Tables are created in the milestone that first needs them (sources + snapshots in M1; organisations + facts/evidence/prompt_runs in M2; opportunities + change_events in M3; review_actions in M4). No speculative future tables; no migration tool in the MVP (SQLite create-on-boot with version-marked schema bootstraps). | Accepted (client §5) |
| **D10** | **Prompt-injection protection is structural, not prompt-based.** Layered defences: (1) JSON-schema validation via Pydantic — structurally rejects malformed payloads; (2) deterministic evidence verification — exact substring match of every quoted fact against the stored snapshot (with whitespace-normalised tolerance); (3) per-source field allowlists cap what any page can influence; (4) audit trail preserves both the raw extracted candidate and verified deltas. Prompt wording tells the model that page text is untrusted data, but rests on the structural gates for the actual guarantee. | Accepted (client §2; implements A4/R4) |
| **D11** | **Deterministic scope-first conflict logic.** Table headings, cell headers and caption text (from `parsing.text_extract`) supply scope keys (service, department, location, e.g. "clinic" vs "pathology collection"). Model-proposed scope is a **fallback**, and unresolved scope is `needs_review` — never silently a conflict, never silently a non-conflict. | Accepted (client §2; implements R5/A4) |
| **D12** | **Conservative duplicate detection, zero auto-merge.** `rapidfuzz` similarity on normalised organisation name + domain + phone-last-4; suggestions only, requiring human confirmation. Values are never merged automatically, even at high similarity. | Accepted (client §2; implements R8/A6) |
| **D13** | **Honest fetch-security posture.** Registered-source allowlist for hosts; scheme validation (https only, http only for localhost fixtures); manual redirect loop with allowlist re-check per hop; blocking of private/loopback/link-local/CGNAT/metadata IP ranges at connect time; mandatory per-host fetch delay (default 3 s); conservative timeouts; retention of prior snapshot on failure; explicit stop on 403/429/auth-walls. **Explicitly not claimed:** complete SSRF immunity — residual DNS-rebinding-style timing windows are documented as a known limitation in `docs/privacy-and-safety.md`. | Accepted (client §2; implements R3/A3) |
| **D14** | **Unverified sources are fixture-only.** r7dd.com remains `manual_fixture_pending_policy_check`: no automated crawling until a human completes the manual robots/terms check and records it in `docs/SOURCE_REGISTER.md`. Until then the pipeline ingests **synthetic fixtures modelling its page structure.** Future live source onboarding follows the documented procedure in the same register. | Accepted (client §3; implements R12) |
| **D15** | **Fixtures are never presented as live scrapes.** Fixture-derived records carry a visible `fixture` provenance label in the sources table, evidence drawer, opportunity cards, exports and all documentation; the demo video and evaluation report state the source of every shown record. Real page HTML is never committed to the repository. | Accepted (client §3) |
| **D16** | **V1 data scope is organisation- and vacancy-centric** (practice name, location, official website, public business phone/email, services/categories, public GP/RN/EN vacancies, full provenance). Named individual-clinician profiling, patient data, sensitive attributes, testimony-derived contact values, personal contact channels, and automated outreach are excluded by design in V1. | Accepted (client §4) |
| **D17** | **Original assessment deliverables kept verbatim as requirements** (client-supplied, not open questions): working project; video ≥ 2 minutes; complete prompt documentation incl. meaningful revisions; accessible project link. | Accepted (client §7) |
| **D18** | **Milestones: M1 is a complete pre-AI vertical slice** (registered source/fixture → parse → DB → FastAPI → minimal React UI). AI extraction (M2) is deferred until the vertical slice is demonstrable end-to-end. Every milestone has independently executable tests and explicit acceptance criteria. | Accepted (client §5; implements R9/A7) |
| **D19** | **Contract authority: Pydantic schemas.** Frontend TypeScript types are generated from the FastAPI OpenAPI schema via `openapi-typescript`; hand-written types are prohibited. A schema drift is a build failure, not a runtime surprise. | Accepted (client §2; implements R10/A8) |
| **D20** | **Evaluation fixtures are synthetic** reproductions of page phenomena (simple pages, multi-scope tables, missing fields, conflicts, GP/RN wording, outdated dates, injection text, malformed HTML, non-healthcare pages) — combined with the redistribution rule, evaluation runs entirely on fixtures and is reproducible without any live fetch. Results are reported as raw counts beside percentages (small-n honesty). | Accepted (client §8; implements R11/A9) |
| **D21** | **Environment hard rules** (verified at review; re-verified before Milestone gates M0 and M6): Python 3.12.6, Node v24.20.0, npm 11.19.0, Ollama 0.40.14, `llama3.2:3b` installed, `nomic-embed-text` installed (and explicitly unused in V1), CPU-only inference. Zero-cost policy: no paid APIs, subscriptions, cloud hosting, commercial automation, or paid dependencies; free/open-source tooling only; no unnecessary infrastructure (client §6). | Locked |
| **D22** | **Component-responsibility, API, validation, error, logging, security, configuration, testing, performance-measurement, evaluation-methodology, reproducibility and documentation standards are normative in ARCHITECTURE §6–§8** — every new module must satisfy them to pass its milestone review; the cycle from client instruction to verifiable acceptance criterion is closed by `docs/IMPLEMENTATION_PLAN.md`. | Accepted (client §8) |
